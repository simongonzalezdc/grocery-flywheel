# Inbox, Calendar, and File Ops

This is the operating home for the new assistant job: keep inbox, calendar, and files moving toward leverage.

## Default Priorities

1. Protect time and attention.
2. Convert raw inputs into next actions.
3. Keep files findable.
4. Surface high-ROI opportunities and hidden obligations.
5. Avoid pretending an item is handled when it is only categorized.

## Inbox Operating Model

Buckets:

- `urgent-action`: needs a reply, payment, scheduling, or decision soon.
- `waiting`: someone else owes a response.
- `opportunity`: money, collaboration, publishing, grant, customer, platform, distribution.
- `reference`: useful but no action.
- `archive/delete`: no useful future value.

Daily inbox output should be concise:

- top 5 required actions
- top 5 leverage opportunities
- waiting-for list
- anything risky or time-sensitive

## Calendar Operating Model

Calendar goals:

- protect deep work blocks
- batch admin and shallow work
- reserve setup time before high-stakes calls
- create visible review windows for content, cluster work, and shipping

Live calendar access is not currently available in this Codex session. Until a calendar connector is available, calendar work should be staged as proposed blocks and scheduling notes here.

## File Organization Model

Sane defaults:

- raw/unclear files land in `00-inbox/`
- active systems and infrastructure live in `01-ai-flywheel/`
- content and media production live in `02-content-engine/`
- personal operating system work lives here
- source-backed notes live in `04-research/`
- old snapshots live in `90-archive/`

File decisions should preserve original files unless deletion is explicitly requested.
